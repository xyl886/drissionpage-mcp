# 02 · 浏览器与并发

## 配置对象：ChromiumOptions

所有启动参数都通过 `ChromiumOptions` 设置，**不要**手动拼命令行。

```python
from DrissionPage import ChromiumOptions

co = ChromiumOptions()

# 浏览器路径（不设则自动查找 Chrome/Edge）
co.set_browser_path(r'C:\Program Files\Google\Chrome\Application\chrome.exe')

# 调试端口与接管
co.set_local_port(9222)          # 固定端口，便于复用/接管
co.auto_port(True)               # 自动分配端口 + 临时用户目录（多实例隔离首选）
co.address                       # 当前地址，如 127.0.0.1:9222
co.existing_only(True)           # 只接管已存在浏览器，不新启动

# 身份与登录态
co.set_user_data_path('./profile')   # 指定用户数据目录（复用登录态）
co.use_system_user_path()            # 用系统默认用户目录
co.set_user('Default')               # 指定用户（多用户目录时）
co.incognito(True)                   # 无痕

# 网络
co.set_proxy('http://127.0.0.1:7890')
co.set_proxy('socks5://127.0.0.1:1080')
co.ignore_certificate_errors(True)

# 性能与显示
co.headless(True)                # 无头
co.no_imgs(True)                 # 不加载图片
co.mute(True)                    # 静音
co.no_js(True)                   # 禁用 JS（谨慎）
co.set_load_mode('eager')        # normal / eager / none
co.set_timeouts(base=10, page_load=30, script=15)

# 其他
co.set_user_agent('...')
co.set_download_path(r'D:\downloads')
co.set_cache_path(r'D:\cache')
co.add_extension(r'D:\ext\adblock')
co.set_argument('--auto-open-devtools-for-tabs')
co.save(r'D:\configs\dp.ini')     # 保存配置，之后用 ChromiumOptions(r'D:\configs\dp.ini') 读回
```

## 启动与接管（两版差异）

```python
# ---- 4.0.5.6 ----
from DrissionPage import ChromiumPage
page = ChromiumPage(co)                  # 启动
page = ChromiumPage('127.0.0.1:9222')    # 接管已开浏览器
browser = page.browser                   # 底层浏览器对象

# ---- 4.1.x ----
from DrissionPage import Chromium
browser = Chromium(co)
tab = browser.latest_tab
browser = Chromium('127.0.0.1:9222')     # 接管
```

**接管已开浏览器的前提**：目标浏览器是带 `--remote-debugging-port=9222` 启动的。
手工启动示例：

```bat
chrome.exe --remote-debugging-port=9222 --user-data-dir="D:\chrome-profile"
```

## 多标签页

```python
tab1 = page.new_tab('https://a.com')          # 新建并打开
tab2 = page.new_tab('https://b.com', background=True)   # 后台打开，不抢焦点

page.tab_ids                    # 全部 tab id
page.tabs_count                 # 数量
page.get_tabs()                 # 标签页对象列表
page.get_tab(1)                 # 按序号（从 1 开始）
page.get_tab(title='标题关键字')  # 按标题
page.get_tab(url='keyword')     # 按 URL
page.latest_tab                 # 最新标签页

tab.activate()                  # 切到前台（两版通用）
page.close_tabs(others=True)    # 关闭其他
tab.close()
```

**注意**：4.1.x 的 `browser.close_tabs(tabs_or_ids, others=False)` 第一个参数是必填的，
不要传 `None`。

## 并发模式

### 方式一：多标签页 + 线程池（推荐，隔离性好）

```python
from concurrent.futures import ThreadPoolExecutor

def fetch(url):
    tab = page.new_tab(background=True)
    try:
        tab.get(url)
        return {'url': url, 'title': tab.title, 'text': tab.ele('tag:body').text}
    finally:
        tab.close()

with ThreadPoolExecutor(max_workers=4) as pool:
    results = list(pool.map(fetch, urls))
```

每个任务独立标签页，互不干扰；标签页用完即关，避免内存堆积。

### 方式二：多浏览器实例（隔离最强，成本最高）

```python
from DrissionPage import ChromiumOptions, ChromiumPage

pages = []
for i in range(3):
    co = ChromiumOptions()
    co.auto_port(True)               # 各自独立端口与用户目录
    co.headless(True)
    pages.append(ChromiumPage(co))
```

适合需要**不同身份/不同代理**并发的场景。注意内存占用随实例线性增长。

### 方式三：SessionPage（无浏览器，最快）

已摸清接口且不需要浏览器环境时，直接走请求模式：

```python
from DrissionPage import SessionPage, SessionOptions

so = SessionOptions()
so.set_proxy('http://127.0.0.1:7890')
so.headers = {'User-Agent': '...'}
sp = SessionPage(session_or_options=so)
sp.get('https://api.example.com/list?page=1')
data = sp.json
```

`WebPage` 则能在两种模式间切换，并互相转交 cookies：

```python
from DrissionPage import WebPage
wp = WebPage()
wp.get('https://site.com')          # 浏览器模式登录
wp.change_mode('s')                 # 切到请求模式
wp.cookies_to_session()             # 把浏览器 cookies 交给 requests
wp.get('https://site.com/api/data') # 用登录态直接请求
```

## 身份隔离的正确姿势

| 目标 | 做法 |
|---|---|
| 每个身份独立环境 | `co.auto_port(True)` 或每次 `set_user_data_path()` 到不同目录 |
| 复用登录态 | 固定 `set_user_data_path()`，先人工登录一次再跑脚本 |
| 完全干净 | `co.incognito(True)` + 临时用户目录 |
| 需要持久化但怕污染 | 复制一份用户目录副本，不在原目录上跑 |

**不要**把生产系统的默认用户目录直接给自动化脚本用，会污染日常浏览环境。

## 退出与清理

```python
page.quit()                      # 关闭浏览器
browser.quit(timeout=5, force=True)
page.disconnect()                # 只断开连接，不关浏览器（4.0.5.6 可用）
page.reconnect(wait=1)           # 断线重连
```

长时间运行的任务建议在 `finally` 里 `quit()`，避免残留 Chrome 进程。
