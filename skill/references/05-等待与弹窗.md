# 05 · 等待与弹窗

## 等待：不要用固定 sleep 硬等

固定 `sleep` 要么浪费时间，要么在慢网下不够。优先用条件等待。

```python
page.wait(1)                     # 固定等待 1 秒
page.wait(1.5, 2.5)              # 在区间内随机等待（更接近真人节奏，反爬友好）

page.wait.doc_loaded(timeout=15)         # 等待文档加载完成
page.wait.load_start(timeout=10)         # 等待页面开始加载
page.wait.eles_loaded('.list', timeout=10)   # 等待元素出现
page.wait.eles_loaded(['.a', '.b'], any_one=True)   # 任一出现
page.wait.ele_displayed(ele, timeout=10) # 等待元素可见
page.wait.ele_hidden(ele, timeout=10)    # 等待元素隐藏
page.wait.ele_deleted(ele, timeout=10)   # 等待元素消失（从 DOM 移除）
page.wait.url_change('success', timeout=15)   # 等待 URL 包含指定文本
page.wait.title_change('结果', timeout=15)     # 等待标题变化
page.wait.download_begin(timeout=30)     # 等待下载开始
page.wait.upload_paths_inputted()        # 等待上传路径写入
```

## 头号陷阱：超时不抛异常

`wait.eles_loaded()` / `ele_deleted()` / `url_change()` 等在超时时
**只返回 `False`，不抛异常**（除非显式传 `raise_err=True`）。
不检查返回值，脚本会带着「没加载完」的页面继续跑，把真正的失败点后移，
排查时非常痛苦。

```python
ok = page.wait.eles_loaded('.result', timeout=10)
if not ok:
    # 必须处理：重试 / 换选择器 / 记录并跳过
    logger.warning('结果区未加载，跳过该页')
    continue
```

## 元素找不到也不抛异常

`page.ele('...')` 找不到时返回 `NoneElement`（falsy），不抛异常：

```python
ele = page.ele('@id=maybe')
if not ele:                      # 必须显式判断
    ...
```

只有**元素已获取后失效**才抛异常（`ElementLostError`），例如页面跳转后
再访问旧元素对象。

## 等接口回来的正确写法

```python
page.listen.start('api/list')
page.ele('@class:next').click()
packet = page.listen.wait(timeout=10)     # 等包本身即是条件等待
```

比 `wait(3)` 再取包稳得多。

## 弹窗处理

```python
page.handle_alert(accept=True)                    # 接受（确定）
page.handle_alert(accept=False)                   # 取消/关闭
page.handle_alert(accept=True, send='输入内容')    # prompt 输入
page.handle_alert(timeout=5, next_one=True)       # 只处理下一个弹窗

# 自动处理：页面频繁弹 confirm 导致脚本卡死时开启
page.set.auto_handle_alert(True)
page.set.auto_handle_alert(True, send='默认输入')
```

`handle_alert` 默认会阻塞等待弹窗出现；页面没有弹窗时不要盲调，
否则会白等到超时。

## 滚动与懒加载

```python
page.scroll.to_bottom()
page.scroll.to_top()
page.scroll.down(500) / .up(500) / .right(300) / .left(300)
page.scroll.to_see(ele)                 # 滚动到某元素
ele.scroll.to_see()                     # 元素自身滚动到可视区
```

瀑布流采集模板：

```python
seen = set()
for _ in range(30):
    items = page.eles('css:.feed-item')
    new = [i for i in items if i.attr('data-id') not in seen]
    if not new:
        break                            # 没有新数据，到底了
    for i in new:
        seen.add(i.attr('data-id'))
        records.append({'id': i.attr('data-id'), 'text': i.text})
    page.scroll.to_bottom()
    page.wait(1.2, 2.0)                  # 等懒加载
```

## 页面一直转圈加载不完

长轮询 / WebSocket / 视频会让 `doc_loaded` 或 `get()` 一直等。处理方式：

```python
page.set.load_mode('eager')      # 只等 DOM 就绪，不等资源
page.stop_loading()              # 强行停止加载
page.set.timeouts(page_load=15)  # 缩短页面加载超时
```

## 超时参数设置

```python
page.set.timeouts(base=10, page_load=30, script=15)
page.set.retry_times(2)                  # 连接失败重试次数
page.set.retry_interval(1)               # 重试间隔（秒）
page.timeout = 15                        # 单次操作基础超时
```

注意：**没有 `page.set.retry(times=, interval=)` 这个方法**（实测不存在）。
次数与间隔是两个独立方法：`set.retry_times(n)` 与 `set.retry_interval(sec)`。
若想在**启动前**设置，用配置对象：`co.set_retry(times=2, interval=1)`。

**建议**：任何等待都显式给 `timeout`，让失败快速暴露，而不是挂死在默认值上。
长循环里尤其如此。

MCP 对应工具：`dp_set_timeouts`（`base` / `page_load` / `script` / `implicit`，
`implicit` 仅 4.0.5.6 有，不支持的版本会自动记入 `dropped`）与
`dp_set_retry`（`times` / `interval`，两个都不传会被明确拒绝）。
页面级重试只在长循环开头设一次即可，不必每页重复设。
