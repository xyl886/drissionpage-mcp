# 06 · 4.0.5.6 与 4.1.x 版本差异

差异是用 AST 静态比对两版源码 + 实机 `inspect.signature` 探测得到的，
比对脚本见 `<repo>/tests\api_diff.py`，原始报告在同目录 `.txt`。

## 一、结构性变化（最关键）

| 项目 | 4.0.5.6 | 4.1.x |
|---|---|---|
| 浏览器对象 | **无顶层 `Chromium` 类**；`from DrissionPage import Chromium` 直接 ImportError | 新增 `Chromium`（`_base/chromium.py`） |
| 页面对象 | `ChromiumPage` **既是浏览器入口又是标签页** | `ChromiumPage` 只代表标签页 |
| 浏览器级方法的归属 | `new_tab` / `get_tabs` / `latest_tab` / `quit` / `close_tabs` 挂在 `ChromiumPage` 上 | 挂在 `Chromium` 上 |
| 底层浏览器类 | `Browser`（`_base/browser.py`） | `Browser` 已移除 |
| 混合页 | `WebPageTab` | `MixTab`（`_pages/mix_tab.py`） |
| 类总数 | 102 | 115 |

### 兼容写法

```python
import DrissionPage as dp

if hasattr(dp, 'Chromium'):            # 4.1.x
    browser = dp.Chromium(options)
    tab = browser.latest_tab
else:                                   # 4.0.5.6
    tab = dp.ChromiumPage(options)      # 页面即入口
    browser = tab.browser
```

判断一定要用 `hasattr`，不要比版本号字符串（有 4.2.0b* / 5.0.0b* 预发布版）。

## 二、方法增删

### 仅 4.1.x 新增

| 类 | 新增 |
|---|---|
| `ChromiumBase` / `ChromiumTab` | `console`、`session`、`find(locators, any_one, first_ele)` |
| `Chromium` | 独立浏览器对象整体（含 `set` / `states` / `wait` / `cookies(all_info)` / `user_data_path`） |
| `Actions` | `drag_in` |
| `Clicker` | `for_url_change`、`for_title_change` |
| `ChromiumFrame` | `sr`、`shadow_root`、`child_count`、`link`、`style`、`tab` |
| `ChromiumPageSetter` | `download_path`、`download_file_name`、`when_download_file_exists`、`retry_interval`、`retry_times` |
| `Settings` | `set_raise_when_ele_not_found`、`set_raise_when_wait_failed`、`set_raise_when_click_failed`、`set_language`、`set_cdp_timeout` 等 |
| `PageStates` | `is_existed`、`is_headless`、`is_incognito` |
| 其他 | `Console` / `ConsoleData`、`CookiesList`、`LocatorError`、`IncorrectURLError` |

### 仅 4.0.5.6 存在

| 类 | 方法 |
|---|---|
| `Actions` | `db_click` |
| `ChromiumPageSetter` | `auto_handle_alert`、`tab_to_front` |
| `WindowSetter` | `fullscreen`、`maximized`、`minimized`、`zoom` |
| 其他类 | `Browser`、`PageWaiter`、`WebPageTab`、`WrongURLError` |

## 三、签名变化（会直接报 TypeError 的）

| API | 4.0.5.6 | 4.1.x | 应对 |
|---|---|---|---|
| `tab.cookies()` | `(as_dict=False, all_domains=False, all_info=False)` | `(all_domains=False, all_info=False)` | 传 `as_dict` 会 TypeError；4.1 需自己把返回的 cookie 对象转 dict |
| `browser.close_tabs()` | `close_tabs(tabs_or_ids=None, others=False)` | `close_tabs(tabs_or_ids, others=False)`，**第一参数必填** | 4.1 下不要传 None |
| `Chromium.quit()` | `Browser.quit(timeout=5, force=False)` | `quit(timeout=5, force=False, del_data=False)` | `del_data=True` 会删用户数据，勿随意开 |
| `tab.s_ele/s_eles` | 无 timeout 参数 | 支持 `timeout` | 传 timeout 在 4.0.5.6 会 TypeError |

## 四、控制台的能力差异

```python
# 4.1.x
tab.console.start()
tab.console.wait().text
tab.console.messages        # 遍历全部日志

# 4.0.5.6：没有 console 对象
# 兜底方案一：注入脚本自采
tab.add_init_js('window.__logs=[];const o=console.log;console.log=(...a)=>{window.__logs.push(a.join(" "));o(...a)};')
tab.run_js('return window.__logs')
# 兜底方案二：CDP 事件
tab.run_cdp('Runtime.enable')
```

## 五、存储写入接口（两版一致，容易记错）

```python
page.local_storage()                 # 读全部
page.local_storage('key')            # 读单项
page.set.local_storage('key', '值')  # 写（注意是 set.local_storage）
page.set.local_storage('key', False) # 删除单项（value=False 表示删除）
```

没有「一次性清空全部」接口，需要先读全部 key 再逐个删。

## 六、错误类改名

| 4.0.5.6 | 4.1.x |
|---|---|
| `WrongURLError` | `IncorrectURLError` |
| （无） | `LocatorError` |

跨版本捕获异常时用 `except Exception` 或做兼容导入，别只 catch 旧名。

## 七、迁移建议

1. **优先使用 4.0.5.6**，除非明确需要 4.1 的 `console` 或新下载设置。
2. 如果要写同时支持两版的代码，把差异收口到一个 `compat.py`，
   全部用 `hasattr` / `inspect.signature` 探测，不要在业务代码里 `if version >= ...`。
3. 升级到 4.1 后重点回归：**下载相关设置**（`set.download_path` 等搬到
   `ChromiumPageSetter`）、**异常抛出行为**（4.1 新增一批
   `set_raise_when_*` 全局开关，默认行为有变）、**`cookies(as_dict=)` 调用点**。
