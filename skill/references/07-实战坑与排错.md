# 07 · 实战坑与排错

本页每一条都是**实测踩到并验证过**的，不是推测。排错时按现象查。

## 一、定位类

### 1. `.cls` 匹配不到（最高频）

`'.read-content'` 会被 DrissionPage 改写为 `@class=read-content` 的**整串精确匹配**，
元素 class 为 `"read-content j_readContent"` 时必然失败。

```python
page.ele('.read-content')          # ✘
page.ele('@class:read-content')    # ✔ 包含匹配
page.ele('css:.read-content')      # ✔ 真 CSS
```

**排错手法**：用原生 JS 数一下到底有没有这个元素，一步区分
「元素不存在」还是「定位语义不对」：

```python
n = page.run_js('return document.querySelectorAll(".read-content").length')
print('原生 CSS 命中数:', n)     # >0 说明元素存在，是 DP 语义问题
```

源码依据：`DrissionPage/_functions/locator.py` 的 `_preprocess()`。

### 2. 选择器作用域太宽，混入脏数据

实跑案例：`.readArea p` 命中 133 个 `<p>`，其中 28 个是页面两侧的推荐位/广告。

**做法**：先锁定最小数据容器，再在容器内 `eles()`，并按 class/文本特征
过滤站点固定广告节点：

```python
container = page.ele('css:div.read-content')
paras = [p.text for p in container.eles('tag:p') if p.text.strip()]
```

分析阶段先用 JS 数清「宽选择器命中数」与「最小容器命中数」的差，
搞清多出来的是什么，再动手写选择器。

### 3. 页面重渲染改变 DOM 结构

部分站点加载后会用 JS 重排列表/目录结构，首次快照看到的层级与稳定态不一致。

**做法**：选择器尽量位置无关，例如
`//h3[contains(., "文字")]/following::ul[1]//a`；
并在**脚本实际运行的时机**复验结构，别只信首次分析。

## 二、生命周期类

### 4. 页面跳转后旧元素全部失效

在页面 A 定位到的元素对象，跳转到页面 B 后再访问会抛
`ElementLostError: 元素对象已失效`。

**做法**：跳转前把需要的数据读成纯 Python 数据：

```python
records = [(a.text, a.link) for a in page.eles('css:.item a')]   # 先转数据
page.get(next_url)                                              # 再跳转
```

### 5. `wait` 超时不抛异常

`wait.eles_loaded()` 超时只返回 `False`。不判断返回值，脚本会带着没加载完的
页面继续跑，把失败点后移。

```python
if not page.wait.eles_loaded('.result', timeout=10):
    logger.warning('结果区未加载，跳过')
    continue
```

同理 `page.ele()` 找不到返回 `NoneElement`（falsy），不抛异常，必须 `if not ele`。

### 6. 长循环必须做单页异常隔离

坏 URL 或导航失败后，`ele()` 可能不返回 None 而是抛
`PageDisconnectedError: 与页面的连接已断开`，脚本直接终止，一章失败毁掉全量。

```python
for url in urls:
    try:
        tab.get(url)
        # ... 采集
    except Exception as e:
        logger.warning(f'{url} 失败: {e}')
        try:
            tab.close()
            tab = browser.new_tab()      # 重建标签页继续
        except Exception:
            pass
        continue
```

配合**逐项落盘 + 断点续传**（记录已完成 URL，重跑自动跳过）。

## 三、取值类

### 7. `attr('href')` 返回绝对化 URL

DrissionPage 对 `href` 做了基于当前页面的绝对化处理：HTML 里写
`/chapter/1.html` 会返回 `https://站点/chapter/1.html`。
再手动拼域名就得到 `https://a.comhttps://a.com/...` 这种坏链接，
坏 URL 还会连带触发上一条的连接断开异常。

```python
url = ele.link                  # ✔ 推荐
href = ele.attr('href')
if href and not href.startswith('http'):
    href = urljoin(base, href)  # 只有确认是相对路径时才拼
```

### 8. `headers` 是 `CaseInsensitiveDict`，不是 dict

它是 requests 的类型，**不是 dict 子类**。`list(headers)` 返回的是 key 列表，
按 `(k, v)` 解包会抛 `ValueError`。

```python
from collections.abc import Mapping
if isinstance(headers, Mapping):
    items = headers.items()
```

### 9. 存储写入必须走 setter

```python
page.local_storage('key')                  # ✔ 读
page.local_storage('key', 'value')         # ✘ TypeError：读接口只收 1 个参数
page.set.local_storage('key', 'value')     # ✔ 写
page.set.local_storage('key', False)       # ✔ 删除（value=False 表示删除）
```

没有「一次性清空全部」接口，需先读全部 key 再逐个删。

### 10. `data:` URL 的 fetch 不产生网络事件

测试监听时用 `fetch('data:application/json,...')` 抓不到包 ——
data URL 由浏览器内部处理，不走网络栈。

**做法**：用真实请求（同源 JSON 文件 / 真实接口）验证监听。

## 四、版本类

### 11. `cookies(as_dict=)` 在 4.1.x 报 TypeError

4.1.x 的 `tab.cookies(all_domains, all_info)` 已移除 `as_dict` 参数。
跨版本代码要么做能力探测，要么统一自己把 cookie 对象转 dict。

### 12. `close_tabs()` 第一参数在 4.1.x 必填

```python
page.close_tabs(others=True)          # ✔ 两版都可以
page.close_tabs(None, others=True)    # ✘ 4.1 报错
```

### 13. 4.0.5.6 没有 `tab.console`

需要控制台日志时：

```python
# 4.1.x
tab.console.start(); tab.console.wait().text

# 4.0.5.6：注入脚本自采
tab.add_init_js('window.__logs=[];const o=console.log;'
                'console.log=(...a)=>{window.__logs.push(a.join(" "));o(...a)};')
logs = tab.run_js('return window.__logs')
```

## 五、通用排错流程

1. **先确认环境**：`python -c "import DrissionPage; print(DrissionPage.__version__)"`。
   版本不同，入口对象就不同。
2. **区分「元素不存在」与「定位语义不对」**：用 `run_js` 跑原生
   `document.querySelectorAll` 对比命中数。
3. **先看页面实际结构再写选择器**：不要凭第一版 HTML 就下结论，
   在脚本运行的时机复验。
4. **定位 API 存疑就读源码**：
   ```python
   import DrissionPage, os
   print(os.path.dirname(DrissionPage.__file__))
   ```
   重点看 `_functions/locator.py`（定位解析）、`_units/` 下各模块（交互/等待）。
5. **用 MCP 单步验证**：`dp_find_element` 会回显解析方式
   （`dp-default` / `attribute` / `css` / `xpath`），能快速判断定位串走了哪条路径。
6. **不确定 API 是否存在**：`dp_doctor` 输出当前版本能力矩阵，别猜。
