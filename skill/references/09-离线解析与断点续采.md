# 09 · 离线解析与断点续采

> 对应 DrissionPage 的 `make_session_ele`，也是 MCP 里 `dp_html_parse` /
> `dp_parse_file` / `dp_html_query` 三个工具的基础。
> 这是真实采集项目里**最高频**的解析方式 —— 本地 462 个采集脚本中有 44 个在用它。

## 为什么要离线解析

浏览器启动、渲染、等待都要时间。同一个页面反复用浏览器定位，成本极高。
标准做法是把职责拆开：

1. 浏览器只负责**把 HTML 取回来**（并处理登录、反爬、JS 渲染）；
2. HTML 落盘（dump）；
3. 之后所有字段提取都在**静态解析**上做。

收益：

| 收益 | 说明 |
|---|---|
| 快 | lxml 静态解析比驱动浏览器快一到两个数量级 |
| 可重跑 | 选择器写错不用重抓，拿落盘 HTML 重试即可 |
| 可断点续采 | HTML 就是断点，进程中断后重跑只补缺失部分 |
| 更稳 | 不受异步渲染、弹窗、网络抖动影响 |

## 基本用法

```python
from DrissionPage._elements.session_element import make_session_ele

html = open('page.html', encoding='utf-8').read()
page = make_session_ele(html)          # 返回 SessionElement

page.ele('@id=title').text
page.eles('css:#list .item')
page.ele('t:a').link
```

也可以从一个元素再解析（把容器单独拎出来）：

```python
container = page.ele('css:div.article')
sub = make_session_ele(container)
sub.eles('tag:p')
```

### 导入路径

实测 4.0.5.6 与 4.1.1.4 **都可用**：

```python
from DrissionPage._elements.session_element import make_session_ele
from DrissionPage._pages.session_page import make_session_ele   # 同上，亦可
```

这是内部模块路径；顶层 `__init__` 并未导出它，所以只能用这个入口。
内部路径虽然「不公开」，但两版都稳定存在。

## 能力边界（实测）

`SessionElement` **具备**：

`ele` / `eles` / `s_ele` / `s_eles`、`text` / `raw_text` / `texts()`、
`html` / `inner_html`、`attr()` / `attrs`、`link`、`tag`、
`css_path` / `xpath`、`parent` / `child` / `next` / `prev` / `before` / `after`（及复数形式）

**不具备**（这些依赖真实渲染或交互）：

`states`、`rect`、`value`、`property`、`click`、`input`、`hover`、
`check`、`drag`、`sr` / `shadow_root`

```python
page.ele('@id=kw').click()
# ✘ AttributeError: 'SessionElement' object has no attribute 'click'. Did you mean: 'link'?
```

→ 需要交互的部分必须在浏览器模式下做；离线树只做**读取**。
（MCP 的交互类工具会直接给出这条提示，而不是抛原始异常。）

## 断点续采模式

真实项目的写法（配合 dump 文件）：

```python
def collect_one(url):
    file_name = url_to_filename(url)          # 例如 url.replace('/', '-') + '.html'
    html = self.get_dump(file_name)           # 1) 有落盘就直接用
    if not html:
        self.page.get(url)                    # 2) 没有才开浏览器抓
        html = self.page.html
        self.dump(html, file_name)            # 3) 抓到就立刻落盘 —— 这就是断点
    page = make_session_ele(html)             # 4) 之后全部离线解析
    return {
        'title': page.ele('t:h1').text,
        'price': page.ele('@class:price').text,
    }
```

四个要点：

1. **先查 dump，再决定要不要抓** —— 重跑时自动跳过已完成项；
2. **抓到就立刻落盘**，不要攒到最后统一写（中途崩溃全丢）；
3. 落盘文件名从 URL 派生，保证可逆映射、可定位；
4. 解析全部走 `make_session_ele`，一次都不碰浏览器。

配合「单页异常隔离 + 逐项落盘」就能做到：任一页失败不影响全量，重跑自动补缺。

## 与 MCP 的对应

| Python | MCP 工具 |
|---|---|
| `make_session_ele(html)` | `dp_html_parse(html=...)` → 返回 `root_id` |
| 离线树上 `page.ele(...)` / `page.eles(...)` | `dp_find_element(root_id=..., selector=...)` / `dp_find_elements` |
| 解析 + 定位一步完成 | `dp_html_query(html=... 或 root_id=..., selector=...)` |
| 从落盘文件解析 | `dp_parse_file(path=..., selector=...)` |
| `make_session_ele(元素)` | 用 `dp_html_parse(html=元素.html)` 变通 |

典型 MCP 流程：

```
dp_html_parse(html="<html>...")                    → root_id
dp_find_elements(root_id="e1", selector="css:.item")
dp_get_text(element_id="e2")
```

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| `AttributeError: no attribute 'click'` | 静态元素不支持交互；改用浏览器模式，或只做读取 |
| 解析出来找不到元素 | 离线 HTML 是**服务端原始 HTML**，不含 JS 渲染结果；需要渲染后的 DOM 请用浏览器侧的 `page.html` |
| 编码乱码 | `make_session_ele` 按字符串解析；落盘/读取统一 UTF-8，非 UTF-8 站点先设 `page.encoding` 再取 `page.html` |
| 感觉解析很慢 | lxml 本身很快，慢通常是落盘 IO，或循环里反复 `make_session_ele` 同一段 HTML；解析结果应缓存复用 |
| 相对链接变成绝对链接 | 离线解析**不会**做绝对化（浏览器侧 `ele.link` 会）。离线拿到的 `link` 可能是 `/detail/1`，需要自己拼域名 |
