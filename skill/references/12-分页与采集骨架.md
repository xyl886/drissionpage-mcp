# 分页与采集骨架

适用：多页列表采集、翻页接口抓取、必须带登录态的长任务。
本篇只讲**流程骨架**（怎么翻页、怎么续、怎么并发、登录态怎么传）；
字段提取见 `09-离线解析与断点续采.md`，反爬见 `11-反爬应对与自愈.md`，定位见 `01-定位与元素.md`。

> 本篇的 cookie 与并发结论均来自实测（`<repo>/tests/probe_api_behavior.py`，
> 可跑 `--cookies-only` / `--threads-only` 复现）；分页骨架提炼自真实采集脚本。

## 一、分页的三种真实写法

### 写法 A：页码可算 → `for` 区间（推荐）

总页数已知时最稳，循环次数确定、便于打印进度、便于中断续跑。

```python
# 版本：4.0.5.6 / 4.1.x 通用
page_count = count_total_page(total, page_size)   # 见第二节
all_items = []

for pgn in range(1, page_count + 1):
    items = fetch_page(pgn)
    if not items:
        break                    # 空页 = 提前结束，别硬跑完
    all_items.extend(items)
    time.sleep(1.5)              # 页间节流，见第三节
```

### 写法 B：页码未知 → `while` 直到空页

列表页「下一页」按钮消失或接口不返回总数字时用。**必须同时设上限**，
否则站点一直返回同一页会变成死循环。

```python
# 版本：4.0.5.6 / 4.1.x 通用
pgn, all_items, seen = 1, [], set()

while pgn <= 200:                # 硬上限：防止站点重复返回同一页
    items = fetch_page(pgn)
    if not items:
        break
    key = items[0].get('id') or items[0]   # 用首条指纹判重
    if key in seen:
        break                    # 翻页参数没生效，站点给了同一页
    seen.add(key)
    all_items.extend(items)
    pgn += 1
```

### 写法 C：第一页单独取（缓存命中 / 断点续采友好）

第一页往往还要顺带拿「总条数」「筛选条件回显」，而且它是重跑时唯一值得缓存的页。
把它从循环里提出来，后面从第 2 页开始：

```python
# 版本：4.0.5.6 / 4.1.x 通用
first = load_dump('page.1.json')          # 先查落盘缓存
if first:
    jobs, total = first['list'], first['total']
else:
    jobs, total = fetch_page(1)
    save_dump('page.1.json', {'list': jobs, 'total': total})

page_size = len(jobs) or 15               # 用首页真实条数当页大小，比写死可靠
page_count = count_total_page(total, page_size)

for pgn in range(2, page_count + 1):
    batch = fetch_page(pgn)
    if not batch:
        break
    jobs.extend(batch)
```

`page_size = len(jobs) or 15` 这个技巧来自真实项目：站点每页实际返回条数常与文档不符，
用首页实测值反推总页数，比信任常量准。

## 二、总页数怎么算（有对错之分）

| 写法 | 15 条/页、共 15 条 | 15 条/页、共 16 条 | 评价 |
|---|---|---|---|
| `total // page_size + 1` | 2 页 ❌ | 2 页 ✅ | **整除时凭空多出一页** |
| `(total + page_size - 1) // page_size` | 1 页 ✅ | 2 页 ✅ | 向上取整，正确 |
| 页面文本 / 接口给的 totalPage | — | — | 以站点为准，但可能不含筛选后的真实条数 |

```python
# 版本：4.0.5.6 / 4.1.x 通用（这是纯 Python 计算，与 DP 无关）
page_count = (total + page_size - 1) // page_size
```

多算一页的代价不只是多发一次请求：**空页会把你的循环打断逻辑踩错**，
所以「算出来的页数」和「`if not items: break`」两重保护都要留。

## 三、页间节流与失败隔离

- **页间必有间隔。** 真实项目用 `time.sleep(1.5)` 页间、`time.sleep(2)` 城市间。
  没有间隔的连续翻页是最容易被判定为爬虫的行为。
- **单页失败不能毁掉全量。** 把每页包在 `try` 里，失败记日志后 `continue`：

```python
# 版本：4.0.5.6 / 4.1.x 通用
for pgn in range(1, page_count + 1):
    try:
        items = fetch_page(pgn)
    except Exception as e:
        logger.warning(f'第 {pgn} 页失败: {e}')
        continue
    if not items:
        break
    all_items.extend(items)
    time.sleep(1.5)
```

- **区分「本页没有数据」和「本页请求失败」**：前者 `break` 结束翻页，
  后者应 `continue` 继续下一页。两者混在一起会导致偶发失败后提前收工。

## 四、登录态：一次登录，多个脚本复用

真实架构是**两个脚本**，不是一个：

```
login.py   扫码登录 → page.cookies(...) → 写 cookie 文件
crawl.py   读 cookie 文件 → 灌回浏览器 / 或拼成 Cookie 头走 HTTP
```

拆开的原因是 `ChromiumPage()` 是**单例**（同一浏览器只对应一个页面对象），
而且扫码需要人等；采集脚本不该再阻塞在人工扫码上。

### 4.1 `cookies()` 的三种读法，字段差别很大【实测】

| 调用 | 返回 | 字段 | 适合用途 |
|---|---|---|---|
| `cookies()` | `list[dict]` | 只有 `name` / `value` / `domain` | 一般读取 |
| `cookies(as_dict=True)` | `dict` | 只有 `name: value` | 判登录、拼 HTTP `Cookie` 头 |
| `cookies(all_info=True)` | `list[dict]` | CDP 原生全字段 | **存盘 + 回灌浏览器** |

实测（4.0.5.6，`probe_api_behavior.py --cookies-only`）：

```
cookies()           → 1 条，字段 ['domain', 'name', 'value']
cookies(all_info)   → 1 条，字段 ['domain', 'expires', 'httpOnly', 'name', 'path',
                                'priority', 'secure', 'session', 'size',
                                'sourcePort', 'sourceScheme', 'value']
as_dict 是否受 all_info 影响: True      # as_dict=True 时 all_info 被忽略
```

源码据此而定：`as_dict=True` 直接返回 `{name: value}`，`all_info` 参数在这一分支不生效。

### 4.2 回灌时的四个坑【实测】

**坑 1：自定义字段会被当成一个 cookie。**
把 `_save_time` 这类业务字段混在 cookie 字典里回灌，会真的写入一个叫 `_save_time` 的 cookie：

```
cookies_to_tuple({'token': 'abc', '_save_time': '123'})
→ 2 条: token='abc' | _save_time='123'
```

所以真实项目里那段 `if k == '_save_time': continue` **不是多余防御，是必需的**。

**坑 2：`cookies(as_dict=True)` 丢掉了 domain。**
它只返回 `name: value`，回灌时 DP 只能拿「当前页面域名」去猜，
跨子域或先设 cookie 后导航的流程就会写错域。

**坑 3：非 http 页面 + 没给 domain → `RuntimeError`。**

```
新建标签页 url='chrome://newtab/'
无 domain 且非 http 页面 → RuntimeError: 未设置域名，请设置cookie的domain参数或先访问一个网站。
带 domain 的单个 dict  → 设置成功
```

只要带上 `domain`，DP 就走 CDP `Network.setCookie`，不依赖当前页面。

**坑 4：只有 `name` 没有 `value` 的字典会被当成「映射」而不是「单个 cookie」。**
DP 靠「是否同时含 name 和 value」区分两种形态：

```
单 cookie dict      → 1 条: token='abc'{'domain': '.example.com'}
简写映射 dict       → 2 条: token='abc' | wt2='def'{'domain': '.example.com'}
只有 name 的 dict   → 1 条: name='only_name'      # 变成了名为 name 的 cookie
```

### 4.3 两种推荐写法

**写法一（推荐）：`all_info=True` 存，list 原样灌。**

```python
# 版本：4.0.5.6 / 4.1.x 通用 —— 存
import json, time
from pathlib import Path

COOKIE_FILE = Path(__file__).parent / 'cookies.json'

def save_cookies(page):
    data = {
        'saved_at': time.time(),                 # 元信息放外层，别混进 cookie 列表
        'cookies': page.cookies(all_info=True),  # CDP 原生字段，可原样回灌
    }
    COOKIE_FILE.write_text(json.dumps(data, ensure_ascii=False, indent=2), encoding='utf-8')

def load_cookies(page):
    data = json.loads(COOKIE_FILE.read_text(encoding='utf-8'))
    age_h = (time.time() - data.get('saved_at', 0)) / 3600
    if age_h > 12:
        print(f'⚠️ cookie 已存 {age_h:.1f} 小时，可能过期')
    page.set.cookies(data['cookies'])            # list 形式，不必手写 domain
```

实测往返一致：`回灌 all_info list → 成功，回读 1 条（原 1 条）`。
DP 内部会自动处理 `expiry`/`expires`、`value=None`、`__Host-` 前缀等情况。

**写法二：`as_dict=True` 存，逐条补 domain（真实项目在用）。**

```python
# 版本：4.0.5.6 / 4.1.x 通用 —— 灌（as_dict 存的场景）
for k, v in cookies.items():
    if k == '_save_time':            # 必须过滤，否则写进一个垃圾 cookie
        continue
    page.set.cookies({'name': k, 'value': v, 'domain': '.example.com'})
```

这种写法的额外好处是同一份 `as_dict` 还能直接拼 HTTP 头：

```python
cookie_str = '; '.join(f'{k}={v}' for k, v in cookies.items() if k != '_save_time')
```

### 4.4 登录成功的判定与清理

用**关键 cookie 出现**判定登录，比等元素出现稳：

```python
# 版本：4.0.5.6 / 4.1.x 通用
LOGIN_KEYS = {'token', 'wt2', 'bst'}
deadline = time.time() + 180
while time.time() < deadline:
    try:
        if LOGIN_KEYS & set(page.cookies(as_dict=True)):
            break
    except Exception:
        pass
    time.sleep(1)
else:
    raise TimeoutError('登录超时')
```

删除与清空：

```python
page.set.cookies.remove('token')          # 删单个（d 模式可传 url / domain / path）
page.set.cookies.clear()                  # 清空浏览器 cookie
```

## 五、运行中凭证失效：原地换 token 重试

长任务跑到一半凭证过期是常态。**不要重跑整个任务**，而是识别业务错误码 →
重新拿凭证 → 存回文件 → **重试当前这一页**：

```python
# 版本：4.0.5.6 / 4.1.x 通用（业务错误码换成你自己的）
def fetch_page(pgn, cookies, token=None):
    res = request_api(pgn, cookies, token)
    if res.get('code') == 0:
        return res['data']['list'], None
    if res.get('code') == 37:                 # 需要安全验证
        return [], res['data']                # 把凭证参数交回上层
    return [], {'error': '未知错误'}

items, need = fetch_page(pgn, cookies)
if need:                                      # 拿新凭证后原地重试同一页
    new_token = refresh_token(cookies, need['seed'], need['ts'])
    if new_token:
        cookies['__zp_stoken__'] = new_token
        persist(cookies)                      # 存回文件，别的脚本也能用
        items, _ = fetch_page(pgn, cookies)   # 只重试这一页
```

要点：**凭证刷新只重试当前页，不重跑前面的页**；刷新成功后立刻落盘，
下次进程启动不用再刷。

## 六、断点续采：先查落盘，再发请求

翻页任务的标准动作是「每页落盘一份，重跑时先读盘」：

```python
# 版本：4.0.5.6 / 4.1.x 通用
def get_page(pgn):
    cached = load_dump(f'page.{pgn}.json')
    if cached:
        return cached
    data = fetch_page(pgn)
    save_dump(f'page.{pgn}.json', data)
    return data
```

好处不只是省请求：**翻页跑到一半被反爬拦掉时，已经拿到的页不用重来**。
落盘后还可以完全脱离浏览器复跑解析（`make_session_ele(html)`），
见 `09-离线解析与断点续采.md`。

## 七、并发采集

**实测结论（4.0.5.6，`probe_api_behavior.py --threads-only`）：**

| 方式 | 结果 |
|---|---|
| 2 线程共享同一个 `page` 对象 × 30 次 `ele()` | 异常 **0** 次，取值不符 **0** 次 |
| 2 线程各用 `page.new_tab()` × 20 次 `ele()` | 异常 **0** 次 |

也就是说，**只读的定位操作在共享页面对象时是稳定的**，不必为了并发强行拆标签页。

但这次实测只覆盖了「定位 + 取文本」。**点击、输入、导航这类会改变页面状态的操作未实测**，
它们天生互相干扰（同一页面同时跳两个 URL 结果不可预期），此时应：

- **每个线程一个标签页**：`page.new_tab(url)`，用完 `tab.close()`；
- 或者**多进程各开独立浏览器**，用 `ChromiumOptions().auto_port()` 隔离端口与用户目录。

```python
# 版本：4.0.5.6 / 4.1.x 差分：4.1.x 用 Chromium(...).latest_tab / new_tab
from concurrent.futures import ThreadPoolExecutor
from DrissionPage import ChromiumOptions, ChromiumPage

def crawl_one(url):
    page = ChromiumPage(ChromiumOptions().auto_port())   # 独立浏览器，互不干扰
    try:
        page.get(url)
        return page.ele('css:.price').text
    finally:
        page.quit()

with ThreadPoolExecutor(max_workers=4) as pool:
    results = list(pool.map(crawl_one, urls))
```

注意 `max_workers` 别开太大：真实项目用 `5~16`，但那是**HTTP 请求**的并发度；
**开浏览器**的并发度要小得多（每个实例几百 MB 内存），4~8 已是上限。

## 八、可直接改的完整骨架

```python
# 版本：4.0.5.6
import json
import time
from pathlib import Path

from DrissionPage import ChromiumOptions, ChromiumPage

BASE = Path(__file__).parent
COOKIE_FILE = BASE / 'cookies.json'
DUMP_DIR = BASE / 'dumps'


def read_cookies():
    if not COOKIE_FILE.exists():
        raise FileNotFoundError(f'未找到 {COOKIE_FILE}，请先运行登录脚本')
    data = json.loads(COOKIE_FILE.read_text(encoding='utf-8'))
    age_h = (time.time() - data.get('saved_at', 0)) / 3600
    if age_h > 12:
        print(f'⚠️ cookie 已存 {age_h:.1f} 小时，可能过期')
    return data['cookies']


def build_page():
    co = ChromiumOptions()
    co.set_local_port(9222)          # 或 co.auto_port() 隔离
    co.headless(False)               # 调试期开有头，便于观察
    page = ChromiumPage(co)
    page.set.retry_times(2)          # 导航失败重试次数
    page.set.retry_interval(1)       # 重试间隔（秒）
    page.set.timeouts(10)            # 元素查找超时
    return page


def main():
    page = build_page()
    try:
        page.set.cookies(read_cookies())     # 先灌 cookie，再访问
        DUMP_DIR.mkdir(exist_ok=True)

        page.get('https://example.com/list?p=1')
        page.wait.eles_loaded('css:.item', timeout=10)

        items = []
        for pgn in range(1, 51):             # 硬上限保护
            dump = DUMP_DIR / f'page.{pgn}.json'
            if dump.exists():                # 断点续采：先查盘
                batch = json.loads(dump.read_text(encoding='utf-8'))
            else:
                batch = [e.text for e in page.eles('css:.item')]   # 换成你的提取逻辑
                dump.write_text(json.dumps(batch, ensure_ascii=False), encoding='utf-8')

            if not batch:
                break
            items.extend(batch)
            print(f'第 {pgn} 页 +{len(batch)}，累计 {len(items)}')

            nxt = page.ele('css:.next')       # 下一页
            if not nxt or not nxt.states.is_enabled:
                break
            nxt.click()
            time.sleep(1.5)                   # 页间节流
    finally:
        page.quit()
    return items


if __name__ == '__main__':
    print(f'共 {len(main())} 条')
```

## 九、自检清单

写翻页采集时逐条对照：

- [ ] 总页数用**向上取整**，不是 `total // page_size + 1`
- [ ] 循环里有**空页 `break`**，且有**页数硬上限**
- [ ] `while` 翻页有**重复页判重**（用首条指纹）
- [ ] 页间有 `time.sleep(1.5)` 这类节流
- [ ] 单页异常被 `try` 包住，失败 `continue` 而不是整任务崩
- [ ] cookie 存盘用 `all_info=True`（或 `as_dict` + 逐条补 domain）
- [ ] 存盘结构里**没有**把 `_save_time` 之类字段混进 cookie 列表
- [ ] cookie 文件记了时间戳，加载时给出过期预警
- [ ] 凭证失效时**只重试当前页**，刷新后立刻落盘
- [ ] 每页有 dump，重跑先读盘
- [ ] 并发时每个线程/进程有独立标签页或独立浏览器，`max_workers` 开浏览器不要超过 8
